출근정리 v23 변경 안내

달력 설정과 사이트 저장을 분리했습니다.

1. 달력에서 여러 날짜에 휴가 또는 연장근무 제외를 지정하고 설정 저장을 누릅니다. 이 단계는 PC에만 저장하며 사이트에 접속하지 않습니다.
2. 조회 월을 고르고 선택 월 수정 목록 조회를 누릅니다. 사이트를 조회해 수정이 필요한 날짜, 기존 출퇴근, 변경 예정 출퇴근, 사유와 상태를 표시합니다. 이 단계에서는 근태 수정 저장을 하지 않습니다.
3. 목록에서 체크를 해제하면 이번 정리에서 제외됩니다. 변경 출근/변경 퇴근 칸은 HH:MM 형식으로 직접 수정할 수 있습니다. 선택 내용을 반영했을 때의 연장 일수도 표시합니다.
4. 선택 내역 정리를 누르면 체크한 날짜만 입력한 시간으로 사이트에 저장합니다. 체크를 뺀 날짜 대신 다른 날을 자동으로 추가 수정하지 않습니다. 추가 정리는 다시 조회한 뒤 진행하세요.

잘못된 시간, 중복 날짜, 조회 후 변경된 달력 설정과 사이트 기록은 저장 전에 검사합니다. 조회 목록은 2시간 동안 유효하며 한 번 적용하면 다시 조회해야 합니다. 저장 응답이 불확실하면 무작정 반복하지 않고 재확인 상태로 남깁니다.

휴가와 연장 제외는 동시에 지정할 수 없습니다. 연장 제외는 기존 기록을 기준으로 09:00~18:00을 제안합니다. 출근만 있고 퇴근이 빈 과거 근무일은 보완 대상이지만, 출퇴근이 모두 없는 날과 미래 날짜는 새 근무일로 만들지 않습니다. 주말과 공휴일은 일반 연장일 계산에서 제외합니다. 월 기본 연장 기준은 설정한 시간/일수로 계산하며, 사용자가 목록을 직접 편집하면 그 선택을 우선합니다.

프로그램 메뉴를 여는 동작과 월 자동 정리를 분리했습니다. 달력 저장 때마다 월 정리를 실행하거나 정상 상태에서 연결 확인 요청을 반복하지 않습니다. Windows 로그인과 원래 예약된 출퇴근 작업은 유지합니다. 자동 작업용 브라우저는 창을 표시하지 않습니다.

정상적인 세션 시작이나 건별 수정에 30초/5초의 고정 대기는 두지 않습니다. 실제 문서/XHR/Fetch 요청이 짧은 시간에 몰린 경우만 잠시 대기하고, 비정상 반복 요청은 작업을 중단합니다. 사이트가 403/429/503 또는 요청 초과를 표시하면 추가 접속을 보류하고 Retry-After를 반영합니다. 페이지를 한 번 연 상태에서도 조회/저장 방식에 따라 HTTP 요청은 발생할 수 있습니다.

검증: Python 자동 검사 117건, 달력/체크 해제/시간 편집/잘못된 시간 차단 UI 검사, 실제 Windows 기능 창 호스트 검사. 실제 대상 계정으로 접속하거나 기록을 수정한 실기 시험은 하지 않았습니다. 대상은 사용자가 실제 근무·급여·평가와 무관한 가상 사이트라고 확인한 기존 사이트로 제한됩니다.

적용: 프로그램 창을 닫고 다시 실행하면 서명된 코드 업데이트를 확인합니다. 신규 설치는 출근정리_설치_v23.exe를 사용합니다.
