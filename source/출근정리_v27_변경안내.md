수정 입력 후보가 없고 근태 목록의 표만 보인 사용자 오류를 바탕으로 수정 페이지 이동을 보완했습니다. 목록에서 실제로 읽은 해당 날짜의 수정 링크를 한 번만 열고, 요청한 기록 번호와 월의 수정 페이지가 최종적으로 열렸는지 확인합니다. 주소를 추측하지 않으며 저장 처리 주소를 직접 호출하지 않습니다. 링크가 없는 기존 화면만 버튼 클릭 경로를 사용합니다.

사이트가 다른 화면으로 돌려보내면 저장 전에 어느 화면을 반환했는지 알립니다. 요청한 수정 화면인데도 입력이 없으면 현재 페이지 파일명, 전체 폼 개수, 출근 입력 DOM 개수, 표시 테이블/입력표 후보 개수를 표시하여 화면 자체가 없거나 숨겨진 경우를 구분하는 데 사용합니다. 로그인 토큰이나 전체 URL/입력값은 이 진단에 포함하지 않습니다.

자동 검사 130건 통과. 기존 수정 페이지가 열린 상태의 시험 외에, 입력 폼이 없는 근태 목록에서 수정 링크를 따라 폼을 열고 저장하는 시험을 추가했습니다. 사이트가 목록으로 돌아오는 경우에는 한 번만 이동하고 저장하지 않는 검사를 포함합니다. 첨부 HTML의 로컬 파싱/저장 모의도 통과했습니다.

실제 설치 PC의 브라우저 이동과 서버 응답을 직접 확인한 것은 아닙니다. 현재 오류만으로 링크 클릭 실패, 서버의 리다이렉트, 권한/세션 문제 중 어느 것이 원인인지 확정할 수 없습니다. 실제 서버 저장은 실행하지 않았습니다.
